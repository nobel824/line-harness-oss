## 文言の決定（2026-08-27・writing-consult / line-step-consult を引いた結果）

### ① 「特別なウェビナーに招待します」は使わない
- **「招待」の方向は正しい**（送り手の在庫報告「用意しています」→ 受け手の地位に主語が移る）
- **「特別な」は却下**。争点マップ §3-1「希少性・限定性の演出 × 景品表示法」は**争点ではなく法令が優先**で、
  **分かれ目は「表示している希少性が実在する事実に基づくか」の一点**。このウェビナーは毎日19〜23時に
  常時開催していて特典を受け取れば誰でも見られる＝**「特別」の実体が無い**
- さらに LINE 規約の禁止の型〈謳い文句〉＋〈**セミナー開催等へ誘導**〉の、**誘導側の翼を濃く塗る文**になる `[公式]`
  （`2026-0803-guideline-bans-the-pitch-not-the-business`）。誘導側は構造上すでに立っているので逃げ場は文言側しかない
- **「ウェビナー」という語も本文では使わず「動画」のままにする**
- **代わりに使える実在の事実**: このリンクは特典返信と翌日フォローにしか入れていないので
  **「特典を受け取った方にだけ、動画を1本ご案内しています。」は事実**。嘘を使わずに「特別」の効果が取れる

### ② 現行の案内文の問題（未改訂）
いまの並びは「あわせて、動画をひとつ用意しています／（約57分）／投稿のテクニックの話ではありません／
インプレッションは出ているのに問い合わせが来ない」。
- **読者が払うコスト（57分）が見返りより先に出ている。** 無料コンテンツで唯一残る反論は「時間」
  （第二の脳: "反論の4分類で洗い出してから潰す" [観察] / 16-objection-proof-cta）
- **「あわせて、」は特典と動画を並列に置く語**で CTA が2本立つ
  （"1通1メッセージ・単一CTAの原則で配信を組み立てる" [観察] / 08-media-specific。ただし「可能な限り」の
  実務観察で実験データは無い）→ **並列をやめて「特典の次の一歩」に従属させれば折衷できる**
- 一番強い「インプレッションは出ているのに問い合わせが来ない」が埋もれている。**痛みを先に立てる**
  （"予防ではなく治療を売る" [観察] / 04-reader-intent。Sugarman の経験則で学術データではない）
- 読者は AI×副業の一般層なので、争点 §2-5 は A 側（ベネフィットへ変換する）を採る

**適用予定の案（未適用）**:

**残すもの**: 「約57分」（隠すと信頼側の反論が立つ。位置を見返りの後に下げるだけ）／
「毎日19〜23時で開始時間を選べます」（時間の反論への回答として機能している）。
**足さないもの**: 「見れば伸びる」系の成果の約束（規約の両翼が揃う）。

### ③ 「なぜ観るのか」の本体は LINE ではなく `intro_text` に置く
LINE 本文は痛み1つ＋リンクに絞り、**リンクを踏んだ先＝すでに一歩踏み出した人**に理由を厚く書く。
二段にすると LINE 側の CTA 分散も減る。

## 配信タイミングの決定（2026-08-27）: **当日同梱のまま維持**

ユーザーから「当日中に見せるより後ろに倒したほうが温度感がいいのでは」という問いが出たが、**現状維持**と判断。

- **前提の整理**: いまの設計は「当日中に全部見せる」ではない。渡しているのは案内で、
  **視聴の開始時刻は本人が毎日19〜23時から選べる**（現に22時の回が選ばれた）
- **型は当日側**: 個人講座系の LINE 導線は5段構造に収束し、**その①が「登録直後の1本
  （あいさつメッセージ or 30〜60分の長尺動画）」**。成約68%の事例は「あいさつメッセージで30分動画を
  見せてから予約導線」`[観察]`（`2026-0803-the-five-stage-consult-funnel`。**ベンダー取材で成功バイアスがかかり、
  失敗事例は実名で1件も見つかっていない**）。同 atom に「**長尺動画1本型のほうが個別相談の申込率が高く、
  5〜10日のステップ配信型は相対的に低い**」という実務者観察もある（％の実測なし）
- **熱は待つと下がる**: 「申し込みたいと思った瞬間が熱量の最高潮で、日程調整に2〜3日かかると冷めて離脱する」`[観察]`。
  自社でも同じ場所で落ちた記録（返信13名に対しフォーム回答3名 / `2026-0802-warm-leads-die-at-the-form`）
- **ただし「何日空けるのが正解か」の公開データは存在しない** `[観察]`
  （`2026-0803-no-public-data-on-step-completion`。ステップ別の到達率・完走率の相場値は2周探索して
  ベンダー記事にも公式マニュアルにも無く、通数・間隔の推奨は例外なく実務者の主観）。
  時間帯の最適解も Braze が自社データで反証済み（`2026-0803-send-time-optimum-is-refuted`）。
  **「後ろに倒すと温度が上がる」も「当日が正解」も断言できる人はいない**
- **決め手はコスト側**:
  - 標準のステップ配信は**即時配信不可・最短で翌日** `[観察]`。いまの即時性は**応答メッセージだから**成立している
  - **応答メッセージは課金対象外** `[公式]`＝**案内を0通で配れている**。
    「特典だけ渡して数日後に案内」に変えると**案内が確実に課金1通、それも全員分**乗る（残枠 約2,000通 `[実測]`）
- リストは1,002人で **A/B の下限5,000に届かない**（`2026-0803-ab-test-needs-5000-reach`）ため統制された検証もできない。
  → **型に合わせて、測れる形で置いておく**。その測定装置が F-8 の段別カウント

### ③ フォーム送信済みの人が相談枠に戻る導線が構造的に存在しない
相談枠ピッカーはウェビナー視聴画面の中にしかなく、**単体のディープリンクが無い**。

**録画 57:06 で「通話のリンクは自動で発行されて、事前にLINEでリマインドが届きます」と明言している**ので食い違う。
→ **ユーザー決定: `submitted_no_booking_*` の2通は出さない。** `booking_url` を NULL のままにして発火させない
（`webinar-followups.ts:314` が両方 NOT NULL を要求）。F-8 の段別カウントで 0 件として見えるので
「黙って死んでいる」とは区別できる。Phase 2 でディープリンクを作ってから有効化する。
`addGoogleMeet` を一般予約経路で一律 ON にする手は、**同じ worker の他2アカウント（クラファン／サガリ藤）の
予約全部に波及する**ので採れない。
