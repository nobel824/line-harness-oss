### ③ 申し込み完了が UI 上わかりづらい問題（実装中）

**原因が特定できた**: 予約が確定しても**シートが閉じて同じピッカーに戻るだけ**で、完了専用の画面も見出しも無い
（`client/webinar/main.tsx` の `PreRegistrationSheet` / `ConfirmRegistrationSheet` が成功時に `onClose()` を呼ぶだけ）。
完了のフィードバックは**画面上部**の緑「✅ 予約済み」カード（`:813-825`）にしか無く、
シートを閉じた直後の視線の位置（画面下部）からは見えない。

**uxw-consult の規範2件がこの欠陥を直接指している**:
- **H-24「SmartHRの結果通知」[規範]** — フィードバックは**直前の操作箇所の近く**に置き、ユーザーに探させない
- **B-34「具体的な成功通知」[規範]** — 成功通知は**対象名付き**で。良「請求書を送信しました」／悪「完了しました」

→ **設計: シートを閉じず、シートの中身を完了表示に差し替える。**「閉じる」を押して初めて `onClose()`。
文言は「申し込みが完了しました」＋`{日時} の回`＋「開始5分前に、LINEで視聴リンクをお送りします。」＋
「このページは閉じて大丈夫です。」＋ボタン「閉じる」。変更時は見出しだけ「変更が完了しました」。

**実装上の罠（プロンプトに明記した）**: `register()` の内部で `load()` が走って親 state が更新され
`registered` prop が変わる。**完了表示中に props 由来の `changing` を参照すると表示が途中で変わる**ので、
成功時点の `sessionStartAt` と `changing` をローカル state に固定する。

**用語が混在している（今回は直していない・要判断）**: 同じ画面に「申し込む」「予約します」「予約済み」が並び、
予約受付メッセージは「受付しました」。uxw の一貫性原則（どちらでもよいが**プロダクト内で混ぜるな**）に反する。
今回は依頼範囲外なので完了表示だけ「申し込み」に寄せた。**統一するかはユーザー判断。**

### ⑪ 追客を視聴の進み具合で出し分ける（同・委譲中）

### ⑭ レビューで見つけた欠陥（PM が自分で発見し修正・`b15ce54`）

**CTA未設定のウェビナーで、完走した人に「お会いできませんでした」が飛ぶ**沈黙故障があった。

旧実装は「viewers に行があれば除外」だったので**挙動の後退**。`COALESCE(..., 0)` で従来挙動に戻した。

**さらに、この修正はテストで守られていなかった**（一次レビューの指摘）。候補SQLのテストはモックで `.all()` の
返り値を直接与えるので、**SQL 本文が壊れても green のまま通る**。`COALESCE` を SQL 文字列で縛るアサーションを足し、
**外すと実際に落ちることを確認**してから戻した。

### ⑬ サクラコメントは使わない（2026-08-27・ユーザーから「盛り上がり感を出したい」と提案があったが却下）

**法令側の論点なので技術論に落とさない。**
launch 争点 §3-2:「**体験していない人の声**、AI生成レビュー、中の人の非開示推薦は **FTC 2024 規則の禁止対象**（米）。
日本は**ステマ規制＋景表法**。ローンチ前に事例が無いなら、**偽事例で埋めない**」。
同 §1 も FTC Consumer Review Rule（偽レビュー・偽体験談・2024-10-21 施行）を挙げる。
日本のステマ規制は「事業者の表示であることを隠して第三者の表示に見せかける」ことを禁じ、**サクラは典型例**。
設計正本 funnel-design も「コメント欄・疑似チャットは置かない（存在しない参加者を演出することになる）」と却下済み。

**疑似ライブ（録画をライブ形式で流す）とサクラは別物**。前者は開催形式の演出、後者は**他人の発言の捏造**。線はここ。

**代替の道はある**: 実在コメントを他の視聴者に見せるなら捏造ではなく、却下理由（存在しない参加者）が消える。

**ただし今は有効化しない** —— `特典請求` タグ保持者が 0人の段階で相互表示を入れると、
**コメントが流れない画面＝「誰もいない」が可視化されて逆効果**。1回あたり数人が同時視聴する状態になってから。
実装は `/state` が返すコメントに当該セッションの `webinar_user_comments` を混ぜるだけで小さい。

### ① 「特別なウェビナーに招待します」は使わない
- **「招待」の方向は正しい**（送り手の在庫報告「用意しています」→ 受け手の地位に主語が移る）
- **「特別な」は却下**。争点マップ §3-1「希少性・限定性の演出 × 景品表示法」は**争点ではなく法令が優先**で、
  **分かれ目は「表示している希少性が実在する事実に基づくか」の一点**。このウェビナーは毎日19〜23時に
  常時開催していて特典を受け取れば誰でも見られる＝**「特別」の実体が無い**
- さらに LINE 規約の禁止の型〈謳い文句〉＋〈**セミナー開催等へ誘導**〉の、**誘導側の翼を濃く塗る文**になる `[公式]`
  （`2026-0803-guideline-bans-the-pitch-not-the-business`）。誘導側は構造上すでに立っているので逃げ場は文言側しかない
- **「ウェビナー」という語も本文では使わず「動画」のままにする**
- **代わりに使える実在の事実**: このリンクは特典返信と翌日フォローにしか入れていないので
  **「特典を受け取った方にだけ、動画を1本ご案内しています。」は事実**。嘘を使わずに「特別」の効果が取れる

### ② 現行の案内文の問題（未改訂）
