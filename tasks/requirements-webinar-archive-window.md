# 要件: アーカイブ視聴を3日間に限定する

対象 repo: line-harness-oss（nobel824 フォーク）。ブランチ `feat/webinar-pre-registration-form`。

## 背景と、いま起きている矛盾

配信終了後の再生（replay）は **`apps/worker/src/routes/webinars.ts:186-192` で無期限**になっている。
コードのコメントにも「入場リンク自体に期限を持たせない」と明記されている。

一方で追客 `registered_no_show`（`webinar-followups.ts:83`）は、予約したのに来なかった人に
「**都合のよい回に選び直せます**」と次の回へ誘導している。**同じ人が入場リンクから今すぐ無期限で見られる**ので、
言っていることと実際の挙動が食い違っている。

さらに予約受付メッセージ（`webinar-reminders.ts:137`）は「**閉じた後も何度でも開けます。**」と
**無期限を明示的に約束している**。

→ アーカイブを**配信終了後3日間**に限定し、上記の食い違いを解消する。

## 実装

### 1. 期限の判定
`apps/worker/src/routes/webinars.ts` に定数を足す:
```ts
// 配信終了後にアーカイブを見られる期間。無期限だと先延ばしを生み、
// 「次の回に選び直せます」と案内している追客とも食い違うため区切る。
const ARCHIVE_WINDOW_SECONDS = 3 * 86400;
```
replay 分岐（`now >= requestedSessionStartAt + webinar.duration_seconds` の条件）に**上限を足す**:
終了から `ARCHIVE_WINDOW_SECONDS` を過ぎていたら **replay を返さず、そのまま下の通常分岐へ落とす**
（＝セッション選択画面 or 待機ルームが出て、次の回を予約できる）。**404 やエラーにはしない。**

### 2. 予約受付メッセージの文言（`webinar-reminders.ts:137`）
現在の `開始5分前にも同じリンクをお送りします。閉じた後も何度でも開けます。` を、次に置き換える:
```
開始5分前にも同じリンクをお送りします。
配信のあと3日間は、このリンクから見返せます。
```
**「何度でも開けます」を残さないこと。** 期限を切る以上、無期限を匂わせる文言は嘘になる。

### 3. 開始5分前リマインドの本文
同ファイル内に開始直前のリマインドを送る箇所があれば、そこにも**同じ期限の記述があるか確認**し、
無期限を匂わせる表現があれば同様に直す。無ければ触らない。

### 4. 追客 `registered_no_show` の本文（`webinar-followups.ts:83-89`）
**まず `registered_no_show` がセッション終了から何時間後に送られるかを調べること**（同ファイルのステージ判定）。

- **終了から3日以内にしか送られない場合**: 本文の冒頭に「アーカイブがまだ見られる」ことを足す。
  ```
  ご予約いただいた「{title}」の回にお会いできませんでした。

  お送りした入場リンクから、配信のあと3日間は見返せます。

  同じ内容を、月・水・金・土・日の20時から開催しています。
  都合のよい回に選び直せます👇
  {pickerUrl}

  ※約57分です。カメラ・マイクは使いません。
  ```
- **3日を過ぎてから送られうる場合**: 期限内・期限切れで本文を出し分ける。
  期限切れ側は現行本文のまま（アーカイブに触れない）。

**どちらを実装したかを報告に書くこと。**

## 受入条件（すべて自分で実行して green を確認）
1. `pnpm --dir apps/worker test`
2. `pnpm --dir apps/worker typecheck`
3. **新規テスト**: 終了から3日以内は replay が返り、3日を過ぎたら replay が返らず
   通常のセッション選択のレスポンスになること（境界値の前後2点）
4. 既存の「予約済み本人が配信終了後に再入場できる」テストが、期限内の条件で通ること

## 制約
- **担当範囲外のファイルを触らない。** 隣接コードを "改善" しない
- 3日という値は**定数1箇所**に置く（マジックナンバーを散らさない）
- **`claude` / `opus-pm` コマンドを呼ばない**（sandbox から Keychain が見えず失敗する）
- **コミットはしない。** 変更を作業ツリーに残すところまで

# 追加要件: 視聴の進み具合で追客を出し分ける

## なぜ

CTA（無料相談）は **`at_seconds=2997`＝49分57秒**に出る。動画内で実際に相談を告知する時刻に合わせてあるので**動かせない**。
つまり**そこまで見ていない人は相談に到達しない**。視聴完走率がそのまま相談数を決める。

ところが現在の追客ステージは
`picker_no_registration`（回未選択）/ `registered_no_show`（来なかった）/ `submitted_no_booking_*`（フォーム後）の3系統で、
**「見たが最後まで見ていない人」を拾うステージが無い**。ここが最大の漏れ。

`webinar_viewers.last_position_seconds` に**どこまで見たかが記録されている**ので、判定はできる。

## 実装

`registered_no_show` を、視聴の進み具合で**3つに出し分ける**。

**ステージは増やさない。既存の排他構造の中で本文だけを切り替える**
（1人が受ける最大通数は4通という設計を崩さないため。ブロック理由1位は「配信頻度が多すぎる」26.5%）。

| 状態 | 判定 | 送る内容 |
|---|---|---|
| **未視聴** | `webinar_viewers` に行が無い | いまの `registered_no_show` の本文＋「配信のあと3日間は見返せます」 |
| **途中離脱** | 行があり `last_position_seconds < 2997`（CTA の位置） | **「どこまで見たか」を出さずに**、続きに何があるかを伝える（下記文言） |
| **CTA到達済み** | `last_position_seconds >= 2997` | **送らない**（CTA を見た上で押していない。ここへの追客は別ステージ `submitted_no_booking_*` の領分） |

**CTA の位置（2997）をハードコードしない。** その webinar の `webinar_ctas` から
`kind='form'` の最小 `at_seconds` を引いて閾値にする。CTA が無いウェビナーでは途中離脱の分岐を作らず、未視聴と同じ扱いにする。

### 途中離脱者に送る本文
```
「{title}」の続きがまだ残っています。

いちばんお伝えしたいのは終盤です。
Xを仕事につなげるために、最後に何から手をつけるかの話をしています。

お送りした入場リンクから、配信のあと3日間は続きをご覧いただけます。

※残りは約{残り分}分です。
```

**「◯分まで見ましたね」と実際の停止位置を出さないこと。** 監視されている印象が離脱を招く。
残り時間は `duration_seconds - last_position_seconds` を分に丸めて出す（1分未満は「あと少し」）。

## 受入条件（追加）
5. `webinar_viewers` に行が無い場合・`last_position_seconds` が閾値未満の場合・閾値以上の場合の3分岐が、
   それぞれ期待どおりの本文になる／送られないこと（閾値の境界値前後も）
6. `webinar_ctas` に form の CTA が無いウェビナーで、途中離脱の分岐に入らず未視聴と同じ本文になること
